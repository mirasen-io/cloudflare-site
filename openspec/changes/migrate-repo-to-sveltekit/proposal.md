## Why

A prepared SvelteKit 2 + Svelte 5 + Skeleton UI v4 + Tailwind v4 project lives under `artifacts/main-web/` as a backup copy, but it cannot be developed against from the repo root. We want to promote that project to the repo root so subsequent route-by-route migration from the legacy `deploy-site/` site can happen incrementally using Skeleton components. This change does not switch the deploy target — the live site continues to be served from `deploy-site/` until routes are ported one by one in follow-up changes.

## What Changes

- Copy the SvelteKit scaffold from `artifacts/main-web/` into the repo root: `src/`, `static/`, `svelte.config.js`, `vite.config.ts`, `tsconfig.json`, `eslint.config.js`, `playwright.config.ts`, `.prettierrc`, `.prettierignore`, `.npmrc`, `AGENTS.md`.
- Replace the root `package.json` and `package-lock.json` with the SvelteKit project's versions, then **add back** `wrangler ^4.93.0` to `devDependencies` and `chess.js ^1.4.0` to `dependencies` (their pre-migration root versions). `@mirasen/chessboard` is dropped from the root manifest. `package-lock.json` is regenerated by `npm install` after these edits.
- Merge `.gitignore`: union of root + SvelteKit, preserving `/artifacts` so `artifacts/main-web/` stays untracked.
- **Do not touch** `wrangler.jsonc` (stays pointing at `./deploy-site`), `deploy-site/` (continues to be the live site), the root `openspec/` (the user will re-init it after migration), `artifacts/main-web/openspec/` (not copied — root keeps its own), or `scripts/`.
- `artifacts/main-web/` stays on disk as a local backup, ignored by git via `/artifacts`.

Out of scope: porting any routes from `deploy-site/` (those happen in follow-up changes), switching `wrangler.jsonc` to serve `./build`, removing `deploy-site/`, replacing or porting `.claude/` settings, configuring Cloudflare GitHub Actions deploy, removing `artifacts/main-web/`, and re-initialising root `openspec/` (the user does that manually once this change is archived).

## Capabilities

### New Capabilities

- `web-app-shell`: SvelteKit 2 + Svelte 5 + Skeleton UI v4 + Tailwind v4 application shell sitting at the repo root, built with `@sveltejs/adapter-static` to `build/`. It coexists with the legacy `deploy-site/` site (which `wrangler.jsonc` continues to serve) so routes can be migrated incrementally from `deploy-site/` to `src/routes/`.

## Impact

- **Code**: new SvelteKit files at the repo root; root `package.json` and `package-lock.json` replaced; `.gitignore` rewritten as a union.
- **Untouched**: `wrangler.jsonc`, `deploy-site/`, root `openspec/`, `scripts/`, `.claude/`, `artifacts/main-web/`.
- **Dependencies**: full SvelteKit/Svelte 5/Skeleton/Tailwind/Vitest/Playwright stack at root, plus `wrangler` (devDeps) and `chess.js` (deps) restored from the previous root manifest. `@mirasen/chessboard` is dropped — re-add explicitly in a follow-up if a ported route needs it.
- **Build & deploy**: `npm run dev` now starts the SvelteKit dev server. `npm run build` produces `build/`. `npx wrangler dev` and any current deploy path continue to serve `deploy-site/` unchanged.
- **Filesystem**: `artifacts/main-web/` remains as the local backup, untracked.
